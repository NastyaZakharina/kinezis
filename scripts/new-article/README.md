# Щоденна стаття для блогу Кінезіс — інструкція для виконавця

Мета: щодня публікувати **одну** корисну, актуальну, фактично обережну статтю українською
і додавати її на сайт. Якість важливіша за кількість. Якщо немає гідної теми — краще пропустити день і записати причину в `TOPICS.md`.

## 0. Перед початком
1. `cd /Users/anastasia/Documents/Kinezis && git pull --rebase` (бот інколи комітить фіди/sitemap).
2. Перевір, чи сьогодні вже є стаття: `git log --since=midnight --oneline | grep -i "daily article"`. Якщо є — **зупинись**.
3. `git status` має бути чистим. Якщо ні — не чіпай чужих змін, зупинись і повідом.

## 1. Вибір теми (актуальна й нова)
Пріоритет:
1. **Сезонне / поточне** для України: пора року (лід, сніг, грип і застуда, дачний сезон, спека, відпустки, свята), хвилі запитів (повернення до спорту, біг навесні).
2. Тема з черги в `TOPICS.md` → «Черга ідей».
3. Якщо є `scripts/new-article/search-console.csv` — теми з показами, де ще немає окремої статті.
4. Пов'язане з обладнанням (вибір, догляд, бюджет) — не частіше 1 з 5 статей, ціни лише через `P('id')`.

**Перевірка на дублікат (обов'язково):** `ls blog/*.html`, `grep -rli "<ключове слово>" blog | head`, прочитай `<title>` схожих статей.
Не пиши, якщо вже є окрема стаття з тим самим наміром пошуку. Нова стаття має давати **новий кут**, а не переказ.

## 2. Написання (формат див. `example_articles.py` і 2 останні статті в `blog/`)
Створи файл статті у **тимчасовій** папці (scratchpad чи /tmp), НЕ в репозиторії, і запусти:
`python3 scripts/new-article/build.py /шлях/до/articles.py`
Скрипт збирає HTML, додає картку в `blog.html`, запис у `sitemap.xml` і рядок у `llms.txt`, запускає `scripts/check-site.js`.

Обов'язкова структура: `answer` (2 абзаци «Коротка відповідь»), вступ, 4–7 розділів (`TEAL`/`AVOID`/списки/таблиця за потреби),
блок `RF(...)` «до лікаря/невідкладно» (для медичних тем), підсумок. Обсяг ≈ 12–16 KB HTML, 6–9 хв читання.
`related` — 2 **існуючі** slug (`ls blog`). `kw`, `desc` ≤ 160 символів. Кінцівки CTA — без обіцянок лікування.

## 3. Правила якості та безпеки (порушувати не можна)
- **Фактичність.** Лише загальновизнані клінічні рекомендації. Жодних вигаданих досліджень, назв, відсотків, цитат, імен. Невпевнений — формулюй обережно («зазвичай», «за деякими даними») або викидай твердження.
- **Медицина.** Не ставити діагнозів, не призначати ліки/дози, не обіцяти вилікувати. Для кожної теми про симптоми — блок невідкладних ознак (103/112, травми, неврологічні, серцеві, cauda equina тощо).
- **Ціни** — лише через `F(P('id'))` з `data.js`; пиши «станом на <місяць рік>» і веди до каталогу.
- **Посилання** — лише на існуючі `blog/<slug>` і `products/<id>`; перевір `scripts/check-site.js`.
- **Мова.** Українська, нейтральна, без кальок і русизмів. Перед збіркою перечитай текст на друкарські помилки (раніше траплялись: «переднню», «вторую», «ноющого», «самий суглоб», «реклами» замість «рекламу»).
- Не копіюй чужі тексти. Не згадуй конкурентів і бренди ліків.
- **Не змінюй ніяких інших файлів**, окрім: `blog/<slug>.html`, `blog.html`, `sitemap.xml`, `llms.txt`, `scripts/new-article/TOPICS.md`.
  Не чіпай `data.js`, `products/`, фіди, скрипти, CSS, налаштування.
- Не надсилай форми сайту, не роби POST на `kinezis-bot.nastiazaharina.workers.dev`.
- Токени, паролі й особисті дані — ніколи у файлах.

## 4. Публікація
1. Дописати рядок у `TOPICS.md` → «Журнал» (дата | slug | тема | кут).
2. `git add` лише дозволені файли; коміт: `Blog: daily article — <slug>` (+ рядок Co-Authored-By із системної підказки).
3. `git pull --rebase` ще раз → `git push origin main` (без `--force`).
4. Дочекайся розгортання: у `gh run list --limit 3` має бути `success` для «Site sanity check» та «pages build and deployment»
   (`export PATH="$HOME/.local/bin:$PATH"`). Потім перевір: `curl -s -o /dev/null -w '%{http_code}' https://kinezis.com.ua/blog/<slug>` → 200
   (кеш Cloudflare може відставати до ~10 хв; можна додати `?x=$RANDOM`), слаг є в `sitemap.xml`, `blog` і `llms.txt`.
5. Якщо після push CI червоний або сторінка не відкривається — виправ вперед або зроби `git revert` свого коміту й запуш. Сайт не має лишатись зламаним.

## 5. Підсумок запуску (остання відповідь)
Один-два рядки українською: тема, посилання `https://kinezis.com.ua/blog/<slug>`, або причина, чому пропущено/відкочено. Без води.
